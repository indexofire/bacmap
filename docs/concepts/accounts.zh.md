# 多用户多角色方案（PLAN #11）

> 状态：设计提案（2026-11-09），待用户确认后进入实施。

## 三种部署模式

```
模式 1：单用户（个人）           模式 2：多用户（单位）          模式 3：多系统（省级/区域）
┌──────────────┐               ┌──────────────────┐          ┌─────┐ ┌─────┐ ┌─────┐
│  bacmap      │               │      bacmap       │          │bm-A │ │bm-B │ │bm-C │
│  (一人用)    │               │  (多 OS 账户)     │          │     │ │     │ │     │
│              │               │                  │          └──┬──┘ └──┬──┘ └──┬──┘
│  全自动化 ✓  │               │  user→admin 审核  │             └───────┼───────┘
│  免登录 ✓    │               │  权限/角色        │                     │
└──────────────┘               └──────────────────┘          ┌──────────────────┐
                               │  安全隔离         │          │   聚合/报告节点    │
                               │  (OS 级)          │          │   (查询多实例)    │
                               └──────────────────┘          └──────────────────┘
```

## 模式 1：单用户（默认，现有）

- Web 免登录（cookie token，本地回环）
- CLI 免登录
- `[plans.auto_confirm]` 可全自动
- **适合**：个人研究者、自动化分析

## 模式 2：多用户（单位部署，如 CDC）

### 架构：多 OS 账户（推荐）

每个用户一个 OS 账户，bacmap 以服务账户运行：

```
┌────────────────────────────────────────────────┐
│ bacmap 服务进程（service 账户，端口 8800/8765） │
├────────────────────────────────────────────────┤
│ Web UI（每个用户浏览器登录 → own token）         │
│ MCP（每个智能体 → own token + profile）          │
└────────────────────────────────────────────────┘
```

### 角色

| 角色 | 权限 | 典型用户 |
|---|---|---|
| `admin` | 全部 + 用户管理 + 策略配置 + auto_confirm 控制 | 系统管理员 |
| `analyst` | 提交分析 + 查看结果 + 审核门（挖掘签字/引用审核） | 实验室技术员 |
| `user` | 提交请求 + 查看自己提交的结果 | 临床/现场人员 |

### 审核工作流

```
user 提交分析请求（Web 表单）
    ↓
analyst/admin 审核 → 转为计划
    ↓
admin 确认计划（或 auto_confirm 策略）
    ↓
分析执行 → 结果生成
    ↓
analyst 审核结果（挖掘门/引用门）
    ↓
user 查看已审核的结果/报告
```

### 技术实现

| 层 | 变更 |
|---|---|
| Web 认证 | 多用户 token（`users` 表 + bcrypt 密码 + 角色） |
| 权限 | FastAPI middleware（角色 → 允许的路由/操作） |
| MCP | 每 token 绑定角色 → 工具带按角色过滤 |
| CLI | `bacmap login`（获取 token 存 `~/.bacmap/credentials`） |
| 审计 | `events` 表已有 → 增加 `actor_role` 字段 |
| 计划 | `PlanService` 增加 `submitted_by_role` → auto_confirm 策略按角色分派 |

### TUI/CLI 登录

```bash
# 首次登录（获取 token）
bacmap login --server http://bacmap.cdc.local:8800
# → 浏览器打开 OAuth 页面 → 或终端输入用户名密码
# → token 写入 ~/.bacmap/credentials（0600 权限）

# 之后的 CLI 命令自动使用 token
bacmap task list
bacmap plan confirm abc123
```

## 模式 3：多系统（区域/省级）

### 架构：联邦模式

每台服务器独立运行 bacmap（数据不出本地网络），上级节点**只聚合报告**：

```
CDC-A (bacmap)     CDC-B (bacmap)     CDC-C (bacmap)
     │                   │                   │
     └─── 聚合查询 ──────┴─── 聚合查询 ──────┘
                │
     ┌──────────┴──────────┐
     │  区域报告节点         │
     │  (只读查询 API 聚合)  │
     │  不存储原始数据       │
     └─────────────────────┘
```

### 技术实现

- 各节点暴露 **只读 API**（`--read-only` 模式 + API token）
- 聚合节点调用各节点的 `/api/v1/stats`、`/api/v1/samples/search`
- **原始序列/敏感数据不出本地**（ADR-16）
- 聚合节点只接收：物种分布、ST 分布、耐药率统计（D0/D1 级汇总）

```bash
# 聚合节点查询
bacmap federate query --node cdc-a:8800 --node cdc-b:8800 \
  --stats "species_distribution,amr_rates" --format table
```
